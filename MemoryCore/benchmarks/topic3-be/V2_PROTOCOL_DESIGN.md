# 下一版 B+E 验证协议设计

状态：设计完成，尚未实现或执行。本文不改变 `topic3-be-v1` 的数据、提示、预测、标签或评分。
真正运行前须填写新目录中的具体 cohort、模型和预算清单；本文件不能当成已冻结的结果协议。

## 目标与竞争解释

主问题：在公开长对话的时间前缀中，来自自然新观察或受控核实的反馈，能否改善下一批来源的记忆核验选择，并保持当前与历史信息正确？零显式反馈指不依赖用户说“你忘了”，不等于没有新观察，也不等于不能使用原题允许的开发期受控标签。

需区分四个解释：候选没有看到变化；E 语义关系错误；生命周期动作错误；reader 没用或不需要这项变化。检索/时间标记的共同工程修复不计为自优化收益。人工确认目标只进入诊断上限，不能作为自主 B 的候选。

消息与 QA probe 使用不同事件类型，防止把评测题当状态写入。

## 事件入口与记忆单元

所有臂通过相同原生接口写入历史。默认使用原文片段，不修改基座抽取模型；如果引入 L1
语义抽取，须增加固定抽取条件对照，另报提取缺失与生命周期错误。

每个新观察进入 `observe(event)`，B 以新来源检索先前同 owner 的记忆；回答检索仍走
`search(query)`。候选保留目标 record/version、来源 span、对象/属性或活动、证据角色、
可见时间、有效时间或 unknown。对象和有效时间可以是候选判断，不能因字段存在就视为真值。

沿用有限候选与容量原则，初始具体预算须在开发前写入运行清单：原生查询条数、每事件候选上限、
每任务 E 上限、来源回读 token 上限、策略容量、超时、reader 输入输出预算。
所有臂共享相同资源上限；额外检索和回读计费。不能用候选已在 QA top-k 中作为唯一准入条件。

## 三种标签分别记录

| 标签 | 要回答的问题 | 不允许代替的结论 |
|---|---|---|
| proposition relation | 两句在各自对象、时间和条件下是否兼容、纠错或证据不足 | compatible 不等于当前用途可无限延续 |
| current applicability | 某个历史证据是否仍能支持给定当前用途 | 当前不适用不等于历史事件为假 |
| transition outcome | 实际不动/追加/限制用途之后，当前与历史探测是否正确 | 结果正确不自动证明原错误由该记忆导致 |

独立标注对齐具体来源和用途，保留不同标注者的分歧。多 agent 复核是分析交叉检查，不当作
专业人工双盲 gold。缺乏可确定证据的样本保留 unknown；官方 QA gold 不改。

## 对照设计

先执行最小主比较；只有出现需解释的差异才运行相应诊断，避免把所有路线堆成昂贵矩阵。

| 角色 | 能看到的信息与行为 | 可归因内容 |
|---|---|---|
| A 原生基座 | 相同原始来源、MemoryCore 原生检索及统一 reader | 必须先存在的基线 |
| B 固定更新 | incoming→历史候选，相同 E、相同来源回读，固定策略 | 入口、组织和普通更新的收益 |
| C 自适应 | 与 B 共同入口和 E，开发期受控反馈更新有界策略后冻结 | 反馈学习的边际效果与成本 |
| D 相同证据的简单对照 | 相同候选与新来源，只链接或追加，不宣称失效；或一次等预算草稿复查 | 更多信息、时间说明、额外推理能否解释收益 |

对 C 的学习归因，用**完全相同示例内容**比较无标签与核实标签；必要时加等预算随机选择。
若样例数量、上下文或调用数不同，须拆开影响，不能宣称标签独立收益。

诊断上限分开记录：给定目标、全量 E、正确证据片段或 oracle 历史。使用 gold 的条件必须明确
标为特权诊断，不与自主发现主成绩汇总。合法“新来源 E”只能读当时已出现/有权读取的来源；
稍后消息可成为延迟反馈，但 E 只能读取当前 checkpoint 已到达的来源。延迟反馈仅影响到达后的
状态与决策，不能回写此前预测，也不能用未来来源定位过去候选。

若固定或自适应臂有局部收益，再对相同 B/E 加一项临时修复 vs 持久更新的配对。比较至少两个
时间有序的后续探测，测持久化是否带来复用收益和历史损害。普通一次复查已经解释全部收益时，
不得把持久记忆更新作为必要组件。

## 学习与验证的边界

首版学习有限条件表或示例池，不先训练大规模模型。输入是合法 Verification 及其来源、耗时、
后续可用性观察；unknown、读失败不作为 same 学习，重复回执去重。按来源/动作/版本隔离，
未见签名回到核验路径。

E 可以是带误差模型，报告模型语义判决与可执行观测的区别。引文存在、JSON 合法、版本匹配均
属于合同检查，不能充当语义置信度。开发期独立关系标签可用于资格评估或受控训练，评估时不可
进入 B、E 或 reader。使用参考答案的训练路线单列，不能改称纯在线自然反馈学习。

闭环在线测试若只观察被选中的 E，应记录选择概率；对 skipped 候选使用事先固定的小比例抽检，
或复用后来本来就要发生的核验。训练期间有完整 E 的离线评估可测选择反事实，但不能声称解决了
在线选择性标签问题。抽检和标注有成本，完整纳入；不靠遗漏 cold start 获得降本结论。

## 指标与失败归因

- 主任务：官方 QA 正确率、逐任务配对胜/负/平；语义错、格式失败与基础设施失败单列。
- B：有独立关系标签的目标进入候选池比例、误归属与 unknown；不将 E-changed 当真变化分母。
- E：按关系/来源类型的条件精度、覆盖与可估计的区间；不以两个模型一致充当校准。
- 生命周期：当前错误使用率、历史问题保留、无关信息损害、恢复成功；无足够标签时报告不可估计。
- 成本：生成和非生成模型 token 分开，读取数量、实际 wall p50/p95、服务时间、失败重试、
  开发取证/学习和每成功总成本。逻辑臂成本与缓存后的实际实验成本分开。
- 集成：关闭绕过 B/E，读失败、损坏、超时硬回退原生结果，跨进程复读；数据库原文保留单列。

官方主问题保持原定义。新增当前/历史/轨迹探测使用事先固定协议，作为公开来源上的辅助诊断，
不把模型自建问答变成唯一主评测。统计按共享来源组聚合，同一事实多个探测不能当独立样本。

## 哪些观察将改变方向

| 观察 | 应作判断 |
|---|---|
| 给定正确目标仍不能改善 reader | 先解决证据用途/reader，而非扩大 B 检索 |
| 已知目标有效，自主候选触达仍低 | B 定位问题成立，研究状态承载者与对象对齐 |
| 固定 incoming 更新解释全部收益 | 工程修复有价值，尚无自优化独立贡献 |
| 核实标签不优于相同无标签示例 | 标签学习假设未成立，不能靠示例变多掩盖 |
| 临时修复等于或优于持久化 | 降低持久动作范围；不据此永久放弃全部生命周期研究 |
| 只省 E 数量却增加陈旧/历史损害 | 报告效果—成本取舍，不称同质量降本 |
| 全部收益由一个任务支配 | 明示逐任务分布，不宣称稳定领先 |
| 可核实变化不足或大量标签歧义 | 收缩为方法验证与标签问题，换有证据的来源而非追分 |

这套设计允许正结果和负结果。其目的在于让每轮实验至少排除一个具体机制解释，保持原题要求的
公开复现、适配、关闭与回退，同时避免把研究预算耗在同一批样本的重复调参上。
