# 不把语境匹配训练成反馈适用真值

本轮关闭一个具体训练捷径：`historical.context_factor == current.context_factor` 只能作为来源语境身份的辅助标签，不能作为反馈适用、内容正确或记忆故障的真值。没有训练新模型，也没有 B 自优化质量结果。

## 证据与复现

独立源码评审核对固定来源 `a8560cab293ae98be4fe260689d58bddf96b51ef` 的 `utils/validation.py:66–85`：同一 factor 可在前后会话拥有不同偏好，因此同语境也可能存在旧要求与新要求。配对元信息不能给逐条反馈自动生成当前有效性标签。参见 [配对合同](PAIR_PROTOCOL.md)。

另外排除此前十二个开发 persona，按 SHA256(`cupid-scope-audit-v1:` + persona) 选择两个新开发 persona，仅取其 consistent 变体的全部八个会话，共十六包。选择独立于语义结果；不将 consistent 选择解释为覆盖偏好改变。审查者只见当前请求和历史正文，不见隐藏 factor、偏好或 checklist。

这是可见证据的助手审查，不是官方 gold 或 factor 分类准确率。`supported` 为“存在至少一项有可见桥接依据的反馈”，不是整段可采用。`unsupported` 表示当前看不到迁移依据，不是已证明使用它一定有害。用途判断有 same 5、different 11；用途不等于数据生成时的语境身份。

## 机制区别

- **语境身份不相同，交付用途仍可能相近。** 化学流程图拆分视觉步骤与当前教学幻灯片不同 factor，审查者认为逐步视觉组织可有限迁移；受众并未完全明示，保留此解释边界。
- **同用途也不能整段迁移。** 作者工作坊强调某次只讲对话真实性，当前是会议指南；作品实例的说明价值可用，不能据此把整份指南限制为只谈真实性。普通课堂幻灯片的隐藏补充笔记也不能连带认可助手给出的软件操作事实。
- **“适用”不等于“带来新增信息”。** 不同用途但 supported 的三例都涉及实例或案例表达，而当前请求已经明确要求出版和写作案例。这支持有限迁移，却不证明记忆带来净收益。本轮没有穷尽标注新增约束，不能把其余 supported 自动算成增量。

这些证据排除了用一个 session 二元标签囊括所有反馈的训练方式。它并不否定学习适用范围；合理粒度应是具体反馈要求以及它的对象、条件和强度。不能把筛选相关会话的收益单独当作 B 创新，也不能把常识推断标成用户明确授予的跨场景许可。

## 下一条学习路线的必要对照

下一实现固定各臂收到的候选证据和检索，学习如何处理反馈。运行时只用当前请求、带来源的用户原话和必要父回复；隐藏 factor、当前参考和变体只进入开发监督或离线评估。B 输出当前可采用的要求、原文依据及约束强度，E 不参与评分。

至少保留当前请求单独输入、冻结普通处理、相同开发原文但无纠正标签、接受受控纠正后更新的有界策略。请求单独输入用于识别参考中哪些内容已明示，不能作为唯一弱基线。后三臂保持相同目标历史与推断预算上限；训练反馈所增加的信息正是干预变量，不能声称连监督信息也相同。记录实际 token 和反馈采集/学习成本。

纠正需分别指出语境错配、旧要求误用、强度削弱，并有原文支持；对有分歧的解释保留未决，不能将本次助手银标硬转真值。更新后在未用于调参的 persona 冻结评估，分别看必要变化、不必要变化、来源支持、强度和新增信息。三种变体是受控替换历史，并非自然追加的连续时间步，不把 consistent→changing 伪造成真实在线反馈轨迹。

上述学习对照尚未实现或运行。只有优于冻结和无标签参照的可解释增益，才支持 B 自优化；不在当前十六会话微调语境词表或删除争议样例。重启 factor 监督仅限明确命名的语境身份辅助任务，并需单独验证它与真实反馈适用性的关系。
