# 从纠正示例到可更新规则：上层机制复核

2026-09-13；候选研究路线，未实施/未跑模型，不改变正在下载模型的固定普通基线协议。

当前已关闭的是“两条全历史画像示例及其纠正直接塞入上下文”的具体配置。片段正确性没有转化成稳定学习收益；这既不能否定反馈学习，也不能证明只需继续增大示例数量。下一需要检验的是反馈能否改变可迁移的解释规则，而非只让旧答案出现在上下文。

## 一手工作与真实依赖

[GEPA 官方仓库](https://github.com/gepa-ai/gepa)把执行轨迹和文本反馈用于反思式候选改写与评价选择。[官方 optimize API](https://gepa-ai.github.io/gepa/api/core/optimize/)明确区分训练输入和用于候选选择的 valset，并提供 metric-call 等停止预算。其 valset 参与搜索，不能在本项目中称为最终未见验收。论文 v2 HTML 本次抓取因体积限制失败；本次机制核查依据官方仓库/API，未声称读完或复现全文。

[ACE v1 §3 与附录 B](https://arxiv.org/html/2510.04618v1)把生成、反思、整理分开，以局部增量更新维护策略上下文；它也明确依赖足够强的反思者，错误反思可能产生有害上下文，并非所有任务都需要丰富长上下文。因此“使用 ACE 形式”本身不能修复反馈真值或反思能力问题。未复现其外部成绩，不把其收益搬到 CUPID。

## 对本项目的判断（推论，不是论文结论）

可尝试把学习状态从“他人的完整画像和参考答案”改为少量可修改的处理规则。规则描述怎样解释反馈的对象、范围和强度，不保存新评估题答案。例如反馈只评价一个局部版本时，应核实能否迁移到当前请求；这只是候选规则形式，不能由研究者写好后包装成模型学会。

反馈编译必须留下输入轨迹、反馈来源、原状态和变更。只允许使用已声明的训练反馈生成或修正规则，包含失败候选；规则上限和反思调用上限预先固定。正确 substring/ID 只证明出处，不证明规则语义或迁移价值。候选规则必须允许被后续相反证据修正，而不是不可反驳的“谨慎”口号。

公平比较至少要能回答两个问题：

1. 同一冻结模型上，有纠正信息生成的规则，是否优于由相同历史/草稿但无纠正标签生成的规则？这才区分反馈价值与普通总结能力。
2. 它是否优于直接读取相同原始反馈？如果只是把更多教师信息送入模型，不能称学习机制改进。若质量相当而成本下降，须计入编译、失败反思与候选选择成本，并报告需要多少后续使用才能摊平。

选择集与最终测试必须按 persona 分开；反复用于选择的集合就是开发集，不可换名为验证泛化。当前强基线六题不参与规则产生/选择；也不拿最新先验要求底稿当新金标准。需要重新明确训练/选择/测试来源后才能执行该候选路线。

当前不采用开放式 GEPA 搜索：我们还缺足够可信且低成本的自动评分，搜索可能放大过强 reference 或主观 reviewer 偏差。可以先做一次有界规则编译和新 persona 对照，质量评价继续区分可见要求、范围错误和参考覆盖。若规则内容趋于空泛、只复述 SYSTEM，或无标签也产生同样规则，要记录“监督没有提供额外可迁移信息”，不通过多轮改写追分。

下一动作仍是完成固定普通模型对照，确认何种证据解释错误真实存在。此文给出候选机制及必要对照，不宣布已经选定新默认算法，也不扩 E。
