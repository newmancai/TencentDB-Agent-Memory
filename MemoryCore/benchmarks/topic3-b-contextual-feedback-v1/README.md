# CUPID：从反馈行为类别转到有语境的偏好内容

**已完成来源审查和真实数据适配，尚未运行模型、评分或学习。** 旧六类分数校准无法提供可靠选择后，本路线改变监督对象，尝试测量“用户反应透露了什么偏好、在什么语境下适用”。不是把最终 QA 提升设为 B 的前置要求，也不重新开始结构化提示词追分。

## 为什么选择这个公开来源

[项目](https://cupid.kixlab.org/)、[官方代码](https://github.com/kixlab/CUPID/tree/a8560cab293ae98be4fe260689d58bddf96b51ef)、[固定数据](https://huggingface.co/datasets/kixlab/CUPID/tree/f6e5fdae9b31f2b400d6ceb281a6a6760cc00309)。作者提供人工筛选的模拟用户交互，不是自然人日志。使用公开发布集，非自建合成样例；其模拟和筛选偏差必须作为外推限制。偏好内容参考可用于方法验证，不是逐消息证据标签或记忆故障真值。

实际756实例/252 persona；每人consistent、contrastive、changing三变体，每实例8段会话、32–129条消息。与短自然反馈分类相比，这里有长交互和跨语境内容对照；相对于既有生命周期实验，主问题放在反馈的含义与适用性，不是更新/删除策略。

## 适配与隔离

`prepare.py` 只向 observations 写入当前请求、历史 role/content 与稳定会话/消息ID；来源、group、split是宿主元数据，模型模板不得直接序列化整个 observation。隐藏 context_factor、contextual_preference、current_checklist 与 instance_type 全部只在 labels 文件。特别是原始 prior_interactions 也带隐藏偏好，不能直接送模型。官方 formatter 同样只渲染历史正文。

按 SHA256('cupid-b-v1:'+persona_id) 排序，以前126 persona作开发、后126作验证，各378实例。同人三变体不拆开；3024种不同历史正文没有跨两侧完全重复。这个检查不证明不存在语义模板近重复。完整哈希、规模与预选首2开发persona/6个联调ID见[准备结果](preparation-summary.json)。本轮未阅读具体题目答案，不把这句话升级为对所有历史使用/模型训练污染的证明。

```bash
python prepare.py --parquet CUPID/test.parquet --out ADAPTED
```

依赖pyarrow。用上述固定revision下载test.parquet；原始数据与正文适配输出存本地，不加入PR。本适配不是MemoryCore集成验收。

## 独立源码审查的边界

官方 inferrer 只见请求+历史正文；用户模拟器按隐藏偏好评价后生成反馈，隐藏评价不等于正文每句都足以支持该偏好。matcher 双向比较预测/参考偏好与checklist，不读历史，因此内容匹配不能证明引用正确或语境适用。官方默认另调模型分解预测checklist，成本应计入。空输出的score/label字段不一致和matcher数量缺少检查是接评估时需处理的合同问题，不能未经验证直接复用统计。

官方 task=both 的回答生成另读完整历史，没有消费推断偏好，不能称B→任务闭环。独立agent已核对这些源码路径。本轮不启动官方全套生成/评估服务，也不修一整套宿主以替代方法实验。

## 下一步顺序与停止条件

1. 先在预选开发persona上跑同信息普通偏好推断基线。模型只看当前请求与八段正文；完整记录输入输出与成本，不静默截断。先判断当前模型是否能从反馈读出内容，普通解释中的正确归属必须计入。
2. 将内容覆盖和证据支持分开检查：官方参考内容可辅助测覆盖；“哪些原文支持/不支持”的标签需独立审查，不能由隐藏生成意图直接充当。若参考需求不在正文可辨识，保留unknown并说明，而非补造证据。
3. 只有发现可跨实例共享的反馈利用缺口，才提出有界策略/状态更新。它必须优于同信息普通利用，并在尚未用于开发的persona上评价；不是更换输出schema本身就是学习。当前尚未确定此学习器，不称完整B自优化方案已实现。

不重跑旧WildChat205调阈值。若普通基线已解决绑定，停止该模型增补；若当前模型普遍缺乏内容推断能力，先区分输入/模型/标签问题，不扩E。最终仍须接入MemoryCore公开长对话runner、验证开关回退并给出移植说明，来源准备不能替代完整交付。
