# B 后见证据反馈：先核验监督对象

2026-09-13。当前仅完成上游调研与两份本地公开数据的结构审计，未运行新模型、未学习、未接E或生产。上一六特征路由配置已关闭；此目录不是新路线有效声明。

## 路线修正

把反馈输出从“猜当前答案错了/哪种审核会赢”改为一个更具体、可复核的对象：**在得到可信的后续答案后，定位先前检索未覆盖的、支持该问题—答案关系的原文。** 这是一条受控反馈假设，不能把公开gold当自然用户确认；真实移植必须由宿主提供带来源的已接受观察，模型自答不能自证。

先评B生成的证据反馈能否命中独立参考证据、提供新增覆盖及成本，再评其是否值得用于后续有界策略更新。不能仅把检索器换强当B创新，也不能以同一道题看过答案后的检索改善冒充未来收益。

## 两项方法参照

[Hindsight（ICLR 2022）](https://people.eecs.berkeley.edu/~matei/papers/2022/iclr_hindsight.pdf)使用答案条件化的后验检索器为仅看上下文的检索器提供监督；它指出上下文相关与目标答案相关不同。这支持训练时利用后见信息的思路，不能直接证明长程记忆反馈有效。本项目不据此重写向量引擎。

[Hindsight Memory-PRM（2026-08-30预印本）](https://arxiv.org/html/2608.29605v1)把检索、引用和受控删除观察用于分配反馈，并区分条目存在贡献与整条动作因果贡献。其干预依赖筛选后的合成探针，单次结果限定于固定reader。论文声称提供复现材料，本轮未核验可下载代码，不称已复现。借鉴的是证据层次与归因边界，不照搬其数值收益或训练体系。

## 实际审计发现

[结构化输出](source-audit.json)，[脚本](audit.py)。文件校验信息在输出中。

* LoCoMo仅取类别1/2/4，共1444题，1438题引用全部精确解析，6题alignment unknown；2132条去题内重复的引用，对应1342条唯一消息，其中518条被多个题引用。重用存在，但没有提供自然发生的QA反馈时间顺序；不能按数组顺序假造在线反馈流。类别3推断和5对抗不并入正证据集。
* LongMemEval-S共500题、23867个session实例、246750个turn实例；896个has_answer=true实例，其中用户842、助手54。不能只保留用户消息而声称完整证据覆盖。
* answer_session_ids共948个按题计数的目标session。94个没有对应has_answer=true的turn：49属_abs题、45属可答题。缺少turn标注不能补负，也不自动判数据错误；session级与turn级覆盖必须分报。
* 13题存在重复session ID，各多一个实例。适配应以问题ID+session位置+turn位置作实例身份，保留原ID离线映射，避免字典覆盖。全部目标session ID至少可定位，无标记turn落在目标session外。
* 模型输入不得包含has_answer、answer_session_ids或携带答案线索的原始session ID。原始答案只能在明确的受控反馈阶段揭示。

[LongMemEval官方说明](https://github.com/xiaowu0162/LongMemEval/blob/main/README.md)分别定义session与turn证据标签。本地实核说明不能假设两者完整一一对应。其500题和LoCoMo十会话此前均已研究暴露，不能重新分组就称独立最终验收。

## 下一实验的最低可解释设计

先用开发来源检验后见反馈的**增量信息**，不是立刻训练新头：同一原始历史、相同候选单位及预算，对比问题检索、仅答案检索、问题+可信答案检索；加入匹配长度的无关答案控制。现成强检索/语义审核需共享相同可见信息；答案字面匹配作为必要廉价基线。报告参考证据recall_any/all、首次新增证据、候选数/token与成本，不把未标注候选计为错误、不能用recall冒充反馈precision。

若后见信号确有增量，再固定来源隔离的先前反馈学习→后续仅问题检索，比较相同状态容量的直接缓存与普通检索增强。若增量只来自答案字符串本身，记录为普通信息增益，不能归功B学习。需要独立语义抽审才能宣称“高置信证据反馈”；需要新的公开来源或明确未暴露协议才能作最终验收。

重启条件：后见观察在运行时有可信来源、原文身份可追溯、反馈定位比同信息强基线有优势或可接受的明确成本收益。缺少任何一项，不转向E补救，也不把一次问答标签拆成伪自然轨迹。当前尚未准备/运行该对照。
