# 当前候选反馈与再检索 v1

运行前固定：复用冻结embedding，对全部精确LoCoMo可答题每来源按reranker-feedback-v1:题ID hash取10，共100开发题。所有来源历史暴露，无未见泛化主张。初检25条，仅Q+单消息正文给Qwen3-Reranker-0.6B，不给当前答案、gold或旧反馈A。官方yes/no前后缀，原始yes-no logit差，4096上限不截断。先建立dense top10、rerank前20→10、rerank前25→10强基线。重排模型输出为受控弱反馈，不是高置信真值。

若普通重排在此队列有基线价值，再测试ReFIT式查询更新：当前前20文档及teacher logits，各自minmax至[0,1]后teacher softmax温度2，student温度1，KL(teacher||student)，100步SGD lr0.005，仅更新当前query向量，重检本来源全部文档取10。全等分数时原查询不动；非有限数/关闭返回原检索。采用论文公开超参，但模型/K不同，仅方法适配，非精确复现。

比较前20普通重排及前25更大重排、固定teacher最高分文档与原query各0.5相加归一的普通反馈扩展。全臂同文本、返回10条；实际teacher评估25、查询更新消费前20，成本分别报告，不把25成本隐藏。重检新候选不追加teacher调用。报告any/all@10、macro参考recall、新增/丢失参考与成本。未标参考非负；不以teacher概率自证置信。若更新无净收益不调步数、温度、K或挑当前失败题。

本轮首先只做候选准备和冻结重排基线。若进入更新，仍是当前任务上的有界反馈优化，非跨轮持久学习；须明确这一边界，并保留后续多轮验证要求。E不介入，未改MemoryCore基座内核。
