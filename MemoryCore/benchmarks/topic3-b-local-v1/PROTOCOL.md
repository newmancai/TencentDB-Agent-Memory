# B 局部证据关系组件实验 v1

在模型输出前固定。使用 DECODE 官方 v0.1 包（见反馈审计）。它验证矛盾告警与证据定位，不验证时间更新、记忆归责或长期业务结果，也不是原题唯一主实验。

按 SHA256(seed=20260913, record_id) 排序，dev 取 64 个基础会话唯一案例作为受控反馈校准，human-bot 取 128 个基础会话唯一案例作为迁移评估；评估排除开发基础会话。不按标签平衡、不挑长短和失败例。不使用 test/A2T/RCT。输入仅 turn_id、speaker、原文，最后一轮为检查目标；persona、writer/verification、矛盾标签及证据索引隔离。

两臂均本地 Qwen3-4B-Instruct-2507，同完整对话、一次 greedy 生成、最多 64 输出 token，32768 输入上限。direct：普通整体判断并给出依据；local：先核对同一主体、属性、条件下不能同时成立的具体陈述，再给判断与依据。输出均为 contradiction 布尔值及历史 evidence ID 列表。两臂交替先后；无示例、无标签入 prompt、无重试追分。形式和预算相同，不把提示差异本身称创新。

报告：二分类准确率、precision/recall、FP/FN、弃权/格式失败、历史证据集合 exact、true-positive 证据命中、输入输出 token 和时延。正例必须关联真实历史 ID；错误 ID 不修补为 gold。输出无矛盾时 evidence 须空；无法合法解析为 abstain。弃权算分类未命中且单独报告，不能因弃权抬高总体成绩。

先完成冻结两臂再看校准反馈。受控反馈仅可用于选择固定臂（以64开发案例的分类准确率为准，平局direct），迁移前固定选择；这是最小有界策略更新基线，不是复杂学习优势。迁移标签不参与选择。报告选择前后和始终direct/始终local；若不能超越两个固定臂，不宣称更强反馈学习。E不参与。

若局部策略没有质量/定位优势，记录具体失败机制，不在当前128例改prompt。若有优势，仍须到公开长对话并接原生MemoryCore验证；本组件结果不能完成总goal。

## v1.1 指标修正（生成完成后，透明保留 v1）

实际 human-bot 正例的 aggregated_contradiction_indices 全为空，该 split 只有二分类标签，不能将空数组当作完整“无证据”gold。v1误将其算作证据exact失败，撤回该定位结论。v1汇总保存在 summary-v1-invalid-evidence-metric.json；v1.1两臂均从同一完整生成回执重算，不改原标注、不筛样本、不新增调用。迁移正例定位指标为 unavailable，开发仍报告有标注的28正例。分类和策略选择不变。另报原始JSON布尔判断，区别语义判断与引用格式弃权，不能据此更换原选择标准。
