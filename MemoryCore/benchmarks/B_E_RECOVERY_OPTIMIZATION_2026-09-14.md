## 发现与修复

1. **容量满后错误地丢弃上下文。** ProjectMemory 默认最多 128 条观察；每次正常 run 会保存
   一条用户任务和一条工具回执，约 64 次任务即可耗尽容量。旧宿主把读取和写入放在同一异常
   处理块中，新任务写入失败就清空已经读出的有效上下文。现在分别处理读取与写入错误，
   保留读取成功的上下文，并明确返回 `memory_error`、`task_persisted`、`receipt_persisted`。
   当前任务另存于本次运行目录，未写入的任务不会假装成为可检索记忆。
2. **检查参数错误发现过晚。** 旧版在模型修改代码后才解析 `--check`。现在模型调用和记忆
   写入前校验 JSON 数组、字符串参数和有效的可执行程序名称；拒绝空名称及 NUL 字符。
   这不提前执行检查，也不保证检查程序的依赖已经安装。
3. **检查中断需要重跑整次任务。** 新版在编码前保存 `task.json`，编码完成后立即保存
   `agent-result.json`，使用完整文件替换避免进程中断时暴露半个 JSON。新增
   `check-run RUN_ID [--check JSON_ARGV]`，用相同 workspace、owner、project 补跑检查。
   每次补跑使用新证据目录，保留原失败结果；检查日志实时落盘，取消返回 130。

恢复检查针对当前工作区，包括用户后来修复的内容。没有编码完成记录时拒绝猜测或自动重跑
模型。它不是未完成编码任务的会话续跑，也没有自动撤销或覆盖工作区。

## 真实接线验证

使用新建的合成两文件导出模块，人工预置两条有前后版本关系的用户规则及 126 条工具回执，
通过原生 ProjectMemory API 达到容量 128。旧规则规定 jsonl 默认值、UTF-8、保留中文、LF
及末尾换行；新规则只改为 csv 默认值并写“其他规则不变”。这些是测试夹具，不是模型学出的规则。

一次真实 Codex 调用实现格式选择和 CSV／JSONL 输出。宿主读取的 scoped 上下文包含当前
引文和历史前任；新任务写入因容量满失败，但已读取的上下文继续进入模型。检查器位于编码
工作区外，启动后主动向 Node 入口发送 SIGINT，随后使用 check-run 补跑。

| 验证项 | 实际结果 |
| --- | --- |
| 编码调用 | 1 次 Codex，完成 |
| 提议编译调用 | 0 次 |
| 容量耗尽时上下文 | scoped，773 字节，保留前任引文 |
| 主动取消检查 | checker_status=cancelled，退出 130 |
| 补跑检查 | 通过，退出 0，新增模型调用 0 |
| 数据库状态 | 仍为 128 条、revision 128；本次任务未写入 |
| 检查内容 | csv 默认值、jsonl 显式覆盖、跨模块调用、中文 UTF-8、LF、末尾换行、空 jsonl |

请求模型 `gpt-5.6-sol`、medium、controlled 配置；CLI 未给出可独立确认的 served model ID。
编码调用输入 96,294 token（缓存 88,192）、输出 2,213（其中 reasoning 字段 813），
耗时 63.256 秒。没有可得美元成本，不据此推算整体成本优势。

原始材料在工作区根目录 `.local-evidence/project-agent-recovery-v3/`。最初两次夹具初始化
把 supersedes 误传成约束对象而非 ID，在任何模型调用前失败；目录 v1、v2 保留，修复后
只有 v3 进入编码。本次不是三轮模型调分。

## 回归验证与仍存缺口

宿主及进程相关 16 项测试、评测工具 15 项测试通过。覆盖容量错误仍保留上下文、坏检查
参数零模型调用、编码完成后宿主中断、检查失败后用户修改再补跑，以及 workspace 不匹配
或编码完成未知时拒绝恢复。扩大运行评测测试时发现旧 MemoryCode 测试夹具漏掉既有 scorer
要求的 shard/model 等运行字段；补齐夹具并验证加载成本按 shard 计一次，评分器和旧成绩未改。
没有修改 TypeScript 核心，本轮不把此前全库测试宣称为重新运行。

本轮主要推进 E 的执行可靠性，并给上一轮历史引文修复增加一次编码接线验证。它不能证明
记忆比原话更好，不能补足 Claude 产品对照，也不能当作真实缺陷修复 benchmark。

容量仍为 128，满后新记忆不能写入；scoped 超预算仍回退完整原话，可能超过目标预算。
下一步容量管理需要把执行日志与可更新的用户来源分开保留，确保归档后更新链和撤销仍可
解析，而不是简单抬高容量或删除旧记录。产品质量验证仍需新真实缺陷、长任务序列与跨文件
依赖，采用同 backend 原话／记忆配对并计入全部成本。
