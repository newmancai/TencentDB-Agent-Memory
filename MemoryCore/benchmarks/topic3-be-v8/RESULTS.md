# B v8：先判断失败是否应归责于记忆

2026-09-13。本轮实现了独立于数据来源的归责输入合同、两种判断方法，以及
由受控反馈拟合的有界选择器。**分步检查恢复了部分检索问题，但没有形成更准确的
总体归责；反馈选择器也没有同预算优势，不升级默认策略。**

关键路线修正是：把“缺少信息的调查候选”与“已确认的记忆故障”分开。
不能仅凭上下文不足、模型自评分或失败回执，授权修改记忆。

## 为什么改线

v7 中正确示例标签主要增加告警，且顺序敏感；同预算排序没有改善。
继续单调校准也不能提高排序。重新查阅的
[matched trajectory replay 研究](https://arxiv.org/abs/2608.26846)区分了
风险校准与额外检索收益估计。这与本地诊断一致，但不是本方法有效的证明。
v6/v7 已提供完整 old/later 证据，重复读取它们不能冒称新增 E 证据。

因此先回到 B 的前置问题：得到一个负面信号后，是否应当归责记忆，以及归责给谁。
[MemTraceBench](https://huggingface.co/datasets/zjunlp/MemTraceBench)提供公开系统
执行图及独立错误归因标签。相关[工作](https://arxiv.org/abs/2605.28732)已研究
操作追踪与归因驱动优化，不能把追踪图或这一总体思路当作我们的独创。
本轮差异是剥除 gold 和 oracle evidence，检验实际可见证据下的归责资格。

## 固定数据与输入

使用 revision `2a12240b36330aab5f40207c078eba0a2cc41194` 下全部七个非 LME
RAG 图，不按模型结果换题：四个 LoCoMo 会话、16 条注释用于反馈拟合；
三个 RealMem 用户、17 条注释用于来源迁移诊断。33 条注释全部保留。
LoCoMo 的标签为 11 RetrievalError / 1 ResponseError / 4 AnnotationError；
RealMem 为 5 RetrievalError / 12 AnnotationError。

上游归因类型/位置经过人工标注与复核，reason 经模型整理；仍不是因果干预真值。
本轮保留 AnnotationError，不能只留下真正的记忆问题再报告精确归责。
这是已经筛选出的失败案例，不测自然任务流中的失败发现率或总体误报警率。
只有三个迁移评估用户，且数据审计已经查看来源及部分标签，不能称严格未触碰验收。

`prepare.py` 从实际 prediction 的依赖边重建 query / retrieved context / answer，
不把 gold、judge、human reason、source_evidence 选择痕迹送模。模型也不接收
文件路径、图注释或原始操作 ID。运行输入与拟合反馈、迁移参考标签分文件；
`evaluate.py` 写完全部预测分数后才打开迁移参考文件。

真实链路是 query → retrieved memory units → formatted context → prediction。
初版单跳假设使 33 条适配失败，已修为真实两跳依赖；失败输出保留，未产生模型调用。
原文含非 BMP 字符，Python code-point 偏移与 JS UTF-16 偏移不同，已明确转换单位。
33 个完整 context 经 native L1 写入/读回，内容及偏移检查全部通过。
**保存外部 RAG 的检索上下文只验证记录合同，不等于重现 MemoryCore 检索故障。**

## 方法和反馈学习边界

- Direct：一轮联合判断，输出 memory / response / no-demonstrated-error / unknown。
- Factorized：先不看回答，判断证据充分性；再独立判断回答误用。宿主按固定规则
  组合阶段：不足→记忆调查候选；足够且误用→回答；足够且未见误用→无可见错误。
- Feedback：只用 16 条 LoCoMo 受控归因反馈拟合两个 logit 特征的 L2 线性排序头；
  不是向提示中追加例子。正则 1，无搜索；最多 32 个反馈样本、三个系数、两个均值和
  两个尺度参数。标签为是否 RetrievalError，得分不是校准概率。

这实现了可测的反馈驱动参数变化，但尚未证明有用。显式开关关闭回到 direct score；
结构损坏、缺失分数或模拟超时回退相同 baseline。只作用于离线调查排序，未挂入
Gateway、未修改检索内核/抽取器、未执行 E 删除或失效。

拟合得到截距 0.6875，标准化特征系数约 -0.26466 / -0.10431。模型权重、提示和
规则未根据 RealMem 输出修改。反馈标签是开发期外部监督，不是自动获得的在线真值。

## 完整输入下的结果（v8.1）

| 方法 | LoCoMo 阶段一致 /16 | RealMem 阶段一致 /17 | RealMem 检索问题命中 /5 | 非记忆被怪到记忆 /12 | RealMem unknown |
| --- | ---: | ---: | ---: | ---: | ---: |
| Direct | 6 | 6 | 0 | 1 | 0 |
| Factorized | 9 | 4 | 3 | 3 | 6 |
| 一律怪记忆 / 训练多数类 | 11 | 5 | 5 | 12 | 0 |
| 一律不怪记忆 | 4 | 12 | 0 | 0 | 0 |

RealMem 分步对直接判断为 3 胜、5 负、9 平。多发现三个检索问题是真实的标签条件下
覆盖修复，但总体一致更低；不能只报 0/5→3/5。恒定“不怪记忆”最高的总体一致也
暴露出标签比例差异，不能把不处理问题当作优化成功。

Actual operation 在候选中触达 17/17（拟合 12、评估 5），Direct / Factorized
迁移命中为 0/5 与 3/5。这由阶段输出映射到宿主已识别的检索/回答操作，
不是在完整执行图中自主定位根因；单一 decisive-operation 标签不排除共同原因。

每个 RealMem 用户固定允许调查一个或两个失败事件，选择只用各组预测分数。
这是每用户已收集失败池的离线分配，不是按时间在线决策。

| 排序方法 | 每用户 1 个：命中 /3 次调查 | 每用户 2 个：命中 /6 次调查 |
| --- | ---: | ---: |
| Direct 的 memory 分数 | 0 | 1 |
| 不充分性分数 | 1 | 2 |
| 受控反馈拟合 | 1 | 1 |
| 固定 ID 顺序 | 1 | 2 |

拟合组每用户两个调查，feedback 为 8/8、insufficiency 为 7/8；迁移后反转。
评估每用户两个时，feedback 相对 insufficiency 为 0 组胜、1 组负、2 组平。
不支持反馈学习净优势。相同调查数量也不等于相同模型成本：Direct 一次判断，
分步/反馈要两次，且拟合采集另外计费。未实际执行核验或测 E 修复收益。

## 独立复盘：不能用一个分类标签跨越证据缺口

独立审查固定排序的两个命中、两个漏检、两个误报，详见
[ATTRIBUTION_DIAGNOSIS.md](ATTRIBUTION_DIAGNOSIS.md)。保留全部原标签与结果：

- 一题通用 CoT 建议没有接续已约定的 sprint；另一题能写 asyncio/httpx 客户端，
  却把多供应商 LLM 接口写成滑雪场项目。领域上能回答不等于接续任务正确。
- 用户只是确认储蓄承诺时，参考答案附带的多个项目推进并不是当轮必需信息。
  缺少那些额外信息不能成为记忆故障证据。
- 产品集成例既缺具体规格，已注入的上下文又有正确产品线索。检索不足与回答误用
  可以共存；强制唯一阶段会丢失这种区别。
- 两处理由表述过宽，一处澄清合理性存在分歧。助手审查不覆盖或替换官方标签，
  也不能由 AnnotationError 推出生成回答必然正确。

因此，B 应先提出**具体的信息缺口及其当轮用途**。要把它升级为可信的记忆归责，
还应验证：用户确实需要这条信息；有权访问的原历史中确实存在可恢复证据；
补回这条证据对错误是否有作用。当前只有 query/context/answer，未观察后两项。
这不是多加一句“谨慎”或调高门槛能够补齐的。

下一步可把这种缺口作为有界调查对象，以普通检索和同预算只读来源恢复作强基线，
用真实前后效果提供反馈。应允许检索与回答共同有问题，并分别报告调查覆盖、无用
核验成本和确认后的归责精度。以上仍是待验证的方向；不在当前 17 题加关键词、改
gold 或扩大模型提示继续追分。若缺口无法从真实可见来源核实，就不授权持久 E 动作。
